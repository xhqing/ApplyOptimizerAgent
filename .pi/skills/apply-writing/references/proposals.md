# 提案模板库（电鸭 · 远程接单场景）

> **定位**：apply-writing skill 的内部参考（本 skill 生成正式提案时加载），供生成「拿来即用」的最终文字用，不是给用户填空的表单。
>
> 2026-09-03 从 ExecutiveAssistantAgent `docs/bidding/bid-templates.md`（程序员客栈 / 猪八戒竞标场景）迁入并按电鸭场景改写。改写原因：电鸭是岗位帖 / 零活帖社区而非竞标平台——雇主发帖描述需求，我们用申请信接触（见 `applications.md`），联系上并初步匹配后，才进入发提案的阶段。**提案是「方案 + 报价」阶段的工件，不是第一句话**。
>
> 版本号规则：`T-<类型>-v<版本>`，类型与台账 `job_type` 一一对应（`AI应用` / `自动化` / `轻量开发`）。台账 `proposal_version` 字段在投出时先记申请信版本（`L-` 前缀），发出提案后追加提案版本（如 `L-评论-v1.0+T-自动化-v1.0`）。每次改动模板必须升版本号并写入文末迭代日志；A/B 测试结论只能经迭代日志入库存——不许凭感觉改模板。

## 使用说明

- **什么时候发提案**：对方已回复、需求方向口头对上了、对方问「具体怎么做 / 多少钱」的时候。对方还没表现出兴趣就甩提案 = 浪费弹药。
- **提案三要素**（继承自原模板库）：**短**（对方 1 分钟能读完，200～400 字正文）、**懂**（开头复述对方的需求细节，证明不是群发）、**稳**（零风险承诺：方案先跑通 / 试用期 / 分阶段付款）。
- **远程特有的信任点**：电鸭雇主最担心的不是技术，是「远程看不见摸不着，怎么知道你靠得住」。每份提案都要覆盖三点——响应节奏（每天几点在线、多久回复）、过程可见（阶段同步 / 演示）、退出机制（不满意时的止损安排）。
- **报价结构**：实施费一次性报，维护费按月另报；金额现场按需求定，模板只锁结构，不锁数字。

## 模板一：`T-AI应用-v1.0`（AI 客服 / 智能体 / 知识库问答）

```
【匹配度分析】
您的岗位帖里提到要解决 X 问题（用对方原话里的细节复述：比如「公众号客服回复不过来」
「客户反复问同样的问题」「咨询集中在晚上没人值班」）。这类需求我做过同类交付，
核心是把「常见问题自动答、复杂问题转人工」这条线搭起来。

【交付方案】
1. 整理您现有的问答素材（产品资料 / 历史聊天记录）建知识库；
2. 主流大模型接入，覆盖常见问题自动回复，答不了的结构化转人工；
3. 部署到您指定的渠道（微信公众号 / 企微 / 网页 / App）；
4. 交付后带 X 次知识库调优（真实对话跑一周后补盲区）。

【合作方式与报价】
- 实施费：XXXX 元（含搭建 + 知识库整理 + 测试上线），启动 30% / 验收 70%；
- 工期：X 个工作日；
- 可选维护：每月 XXXX 元（含迭代、知识库更新、故障处理）；
- 合作节奏：每天 X:00–X:00 在线，消息 X 小时内回复，每 X 天同步一次进度。

【我的差异】
AI 应用交付是我的主业，工具链成熟，交付速度比传统开发快 X%；正式合作前可先做一个小样
（拿您 20 条真实问题跑一版自动回复给您看效果），小样满意再谈钱。
```

## 模板二：`T-自动化-v1.0`（自动化工作流 / RPA）

```
【匹配度分析】
您描述的 X 流程（复述对方的节点：比如「每天要从 3 个群收报名表、手动汇总成表格、
再群发通知」），目前每周大约耗 X 小时人力。这类流程我做过同类自动化，
节点清晰、规则稳定，是自动化性价比最高的场景。

【交付方案】
1. 先按您的描述画一版流程图（附后），您确认节点无误再动手；
2. 自动化串联数据获取 → 处理 → 输出 → 通知全链路，跑通后人工只处理异常分支；
3. 交付操作手册 + 一次维护培训，您团队自己能改简单配置。

【合作方式与报价】
- 实施费：XXXX 元，方案先跑通再收尾款（您这边的风险最小）；
- 工期：X 个工作日；
- 试运行：交付后 X 天内免费修正；
- 合作节奏：每天固定时段在线，进度每 X 天图文同步一次。

【我的差异】
我日常生产方式就是「人 + AI 工具链」协作，同类流程已交付 X 个；交付物包括源码 / 配置
和文档，不绑架您后续必须找我维护。
```

## 模板三：`T-轻量开发-v1.0`（小程序 / 小工具 / 轻量 Web）

```
【匹配度分析】
核心功能：① … ② … ③ …（复述对方列的功能点）；目标用户：…；关键约束：…
（预算 / 期限 / 平台）。这类轻量开发我用 AI 辅助方式做，同等功能工期比传统方式短、
报价有空间。

【交付方案】
1. 流程：原型确认 → 开发 → 测试 → 上线，每阶段您验收后才进下一阶段；
2. AI 辅助开发压缩工期，但测试人工把关，不交付没验证过的东西；
3. 交付源码 + 部署文档，后续您可以找任何人维护，不被锁死在我这里。

【合作方式与报价】
- 费用：XXXX 元，分阶段付款（启动 30% / 原型确认 30% / 上线验收 40%）；
- 工期：X 周，逾期按天减免费用（写进约定）；
- 免费维护：交付后 X 个月；
- 合作节奏：每天在线时段 X:00–X:00，每周一次进度演示。

【我的差异】
AI 辅助开发是我的日常生产方式，不是宣传话术；同等功能报价普遍低于传统开发；首单可
缩小范围先跑一版（核心功能先上线，其余二期），验证我的交付质量再扩大合作。
```

## 场景话术库（配合提案使用）

### 破冰（无历史案例时）

> 我目前可全职投入远程协作，交付用 AI 工具链加速，响应快。可以先做一个小样 / 试运行验证效果，满意再谈合作——您先说说具体需求？

### 报价异议 / 讨价还价

> 理解预算考虑。可以在范围上调整：核心功能先交付，其余做成二期；或者先按最小范围跑通一版，验证有效再扩展。质量对应的工时是有底线的，低于底线的报价我宁可不做，也不交付坑您的半成品。

### 对方要求比稿 / 免费出完整方案

> 我可以先给一页「需求理解 + 方案概要」（不含实现细节），方向确认了再谈合作。完整方案需要投入实际工作量，不便免费提供——但概要足够您判断我懂不懂这个需求。

### 转维护（单子交付后）

> 这个系统我已交付并测试通过。后续可以由我持续维护，每月 XXXX 元，含功能迭代和故障响应——我刚做完这个系统，由我维护的切换成本最低。不需要也没关系，交付文档齐全，您可以找任何人接手。

## 避坑清单（电鸭版，迁入时重写托管相关条目）

原清单按「平台资金托管」写（程序员客栈 / 猪八戒语境）；**电鸭是社区不是托管平台，没有资金托管这一层**，付款安全靠「分阶段收款 + 合同」自己搭建：

- ❌ 不投：比稿 / 免费方案单（先交完整方案再谈钱，白干风险）。
- ❌ 不接：拒绝任何阶段付款、要求全部做完一次性结账的单（风险全部在我方）；金额较大或条款复杂的，先过 Justin（法务）再签。
- ❌ 不投：需求描述含糊、没有任何背景信息的帖——连匹配度分析都写不出来的，pass。
- ❌ 不投：工期离谱（几天交付完整系统）或预算明显低于行情的单。
- ✅ 必做：每单交付后请对方给评价 / 留合作痕迹——远程接单没有平台信用分，口碑案例就是唯一复利资产。
- ✅ 必做：报价前先问清预算区间（谈单日志记「报价」条目）；预算问晚了是输单高频输因（见 SOP 4.3 输因表）。
