# 求职侧模板库（招聘平台 · 正式工作求职）

> **定位**：apply-writing skill 的内部参考（求职侧——主渠道 BOSS直聘，可扩展其它招聘平台），供生成「拿来即用」的最终文字用，不是给用户填空的表单。
>
> 与接单侧的关系：匹配度分析四段结构、A/B 测试纪律、台账衔接**全部共用**（见 `applications.md` / `proposals.md`）。差异三点——
> ① **载体**：BOSS IM 首条招呼（短、钩子前置）+ 在线简历（HR 关键词搜索 + 系统评分双重筛选）；
> ② **薪资口径**：坐班岗按全职月薪；远程岗按组合收入逻辑——远程多项目并行是既定经营方式，单岗收入只是组合一部分，fit_score 薪资维度显著放宽（CLAUDE.md 2026-09-05 规则）；
> ③ **决策链**：接单侧对方是用人者本人（电鸭雇主），求职侧隔着 HR 层——首条招呼的第一读者是 HR 而非用人经理，钩子要过 HR 的筛（关键词、匹配度一目了然），用人经理关心的深度证据留到简历和面试。
>
> 渠道分工：**电鸭全职岗**的接触仍走 `L-私信`（`applications.md`），进入发简历 / 谈薪 / 面试阶段后改用本参考；**BOSS 及其它招聘平台**从打招呼起全走本参考。
>
> 版本号规则：`B-打招呼-v<版本>`（招聘平台首条招呼 / 投递附言）、`J-简历-v<版本>`（简历定制改版）。台账 `proposal_version` 衔接：招呼投出记 `B-打招呼-v1.0`，发简历后记 `B-打招呼-v1.0+J-简历-v1.0`（与接单侧 L+T 组合模式一致）。薪资与面试话术暂不单设版本，随 B-/J- 迭代日志一并记录。

## 一、打招呼话术（B-打招呼）

### 平台事实（2026-09-07 调研）

- **系统默认招呼语回复率趋近于零**——每条都自定义写，禁用「您好，我对这个职位很感兴趣」式开场。
- **HR 批量处理招呼**：消息列表里只有首行可见，钩子必须放最前面（列表预览就含 JD 细节或证据，不含自我介绍）。
- **BOSS 用关键词匹配 + 内容评分自动筛在线简历**：JD 里的关键词（技术栈、领域词、职级词）必须出现在招呼与简历里，否则到不了 HR 眼前。
- 平台机制会持续变，每次生成前若用户描述与上述事实冲突，以用户观察为准并记入迭代日志候选。

### 结构（四段结构压缩版，100～200 字）

| 段 | 写什么 | 压缩自 |
|---|---|---|
| ① JD 细节钩子 | 一句复述 JD 特有的痛点 / 场景 / 约束（不是照抄职位名），放首行 | 段①需求复述 |
| ② 能力对照一句 | 对方最核心的一条要求 + 我做过对应什么 | 段②能力对照 |
| ③ 证据一句 | 交付物 / 仓库 / 可演示小样，落到具体可核验的名词 | 段③相关证据 |
| ④ 低门槛收尾 | 一个小下一步（发简历 / 发小样 / 约简短沟通），不逼承诺 | 段④差异化 |

### 场景示例（占位演示，非真实 JD）

**示例一：坐班全职 AI 应用岗**

```
您好，看到贵司在招 AI 应用工程师——JD 里提到「客服咨询量大、要在大模型问答里
解决答不上来的转人工问题」，这正是我做过完整闭环的场景：大模型知识库客服系统，
真实问答素材建库 + 结构化转人工，上线后夜间咨询全自动覆盖。代码与演示：
github.com/xhqing。方便的话我把简历发您，或约 X 分钟电话细聊。
```

**示例二：远程全职 AI 工程岗**

```
您好，这个远程岗要「独立负责 AI 功能从原型到上线」——看 JD 强调远程自驱和
无人带教的独立交付，我的工作方式正对口：AI 应用从知识库、Agent 到渠道部署
全链路独立交付过 X 个，仓库与演示 github.com/xhqing；日常响应节奏 X 小时内。
简历可以直接发您，附一个可演示小样。
```

### 红线

- ❌ 复述不出 JD 细节 = 不发（与接单侧同规则）。JD 只有职位名没有业务描述的岗，先 pass 或向用户要补充信息。
- ❌ 首条招呼不谈薪资。期望薪资是面试后期动作；HR 首聊就问的，用第三节推迟话术。
- ❌ 不写「精通 / 熟练掌握」自评清单，只写做过什么 + 证据在哪。
- ❌ 不群发感：每条单独写，宁可少投。投出即记台账（SOP 触发器 2）。
- ✅ 在职状态保持「在职-考虑机会」，不主动改为「离职-随时到岗」——在职身份是谈薪筹码。

## 二、简历定制要点（J-简历）

- **JD 关键词对齐**：技术栈、领域词、职级词逐条核对进简历——这是 BOSS 自动筛的第一道关；但只放真做过的词，不堆砌。
- **证据密度红线**（同申请信）：每条经历带可核验结果（数字、交付物、链接），「精通 XX」式自评清零。
- **一岗一改**：投递前按 JD 调整项目顺序与关键词权重；改动即升 `J-简历` 版本号，台账记当次版本。
- 简历本体的一次性大改版（结构、经历重写）按模板迭代纪律走：A/B 依据或输因复盘触发，不许凭感觉改。

## 三、期望薪资话术库（不单设版本号）

**开口前功课三线**（必做，数字属敏感信息只记本地，不进任何 git 跟踪文件）：底线（低于不谈）/ 目标值 / 开口价（目标值 +15%～20% 留还价空间）。行情来源：OfferShow、脉脉、看准网、JD 挂牌区间。

**两条口径**（CLAUDE.md 2026-09-05 规则，不混用）：
- 坐班岗 → 全职月薪口径；
- 远程岗 → 组合收入口径（各项目组合月均收入），单岗月薪可显著放宽，尤其工时自由、可并行的岗。

### HR 首聊就问期望薪资（推迟）

> 薪资是我看重的因素之一，不过想先确认岗位匹配度——方便先介绍下这个岗最核心的考核点吗？数字等双方都对上了再细聊，免得互相浪费机会。

### 必须先报（先问结构，再报区间高位 + 条件）

> 方便先了解下这个职级的薪资结构吗——base 和奖金 / 补贴的大致比例？我好给出更匹配的数字。

对方仍要你先报：

> 如果要一个数字：期望 XX～XX（窄区间，跨度大等于按最低处理）。这是基于 base 的预期，如果总包的奖金 / 补贴有竞争力，base 上我可以灵活。

### 对方说「超出预算」

> 方便透露下大致预算范围吗？我想看看差距在 base 还是总包——如果年终奖和福利补得上，base 这块可以谈。

不立刻降价、不直接离场；对方报的数可能是开场测试，不是真实上限。

### 对方问上家薪资

> 具体数字不方便透露，我直接说期望更有参考性：XX。上家的薪酬结构和这个岗可比性不大。

不必然如实报历史值，把话题锚到期望值。

### 技术面被问薪资

> 薪资想留到 HR 面细谈——先请教您：这个岗技术上最想解决的一个问题是什么？

技术面官不主导薪资，轻描淡写推过去。

### 远程岗被问期望薪资（组合收入口径）

> 我的口径是组合收入：目前手头项目组合月均约 XX。这个岗如果工时灵活、可与现有项目并行，期望 XX 即可——具体看贵司对每周投入时长的要求。

### 报价后纪律

- 报完数字**不主动降价**；对方沉默多半在走流程，等对方开口。
- 「我比较灵活 / 您看着给」= 没有自我定价能力，禁用。

## 四、面试话术骨架

- **自我介绍（60～90 秒）**：身份一句 → 与该岗最相关的一段经历 + 数字证据 → 为什么是这个岗（复用招呼里的 JD 细节钩子，证明 continuity）。
- **项目讲述**：背景 → 任务 → 我做了什么 → 结果带数字；每个主项目备一个「最难的点 + 怎么解的」。
- **离职原因红线**：不贬前东家、不编故事；在职现状如实（「在职，看新机会」）。
- **面试后跟进**：24 小时内一条信息——感谢 + 针对面试中没答好的一处补充证据。投出 / 面完记台账。

## 五、避坑清单（BOSS 版）

- ❌ 不投：JD 无具体业务描述、写不出匹配度分析的岗（与接单侧「需求含糊不投」同规则）。
- ❌ 不投：薪资明显低于行情、还要求尽快到岗救火的岗。
- ❌ 不在在线简历 / 招呼里填真实底薪预期——期望薪资字段按渠道口径填区间，谈判空间留到 HR 面。
- ✅ 必做：招呼投出即记台账（SOP 触发器 2），带 B-/J- 版本号。
- ✅ 必做：面试前查公司薪资行情、定好三线（底线 / 目标 / 开口价）。
- ✅ 隐私：BOSS 在线简历含真实联系方式与在职状态，与电鸭「对搜索引擎隐藏姓名」分开管理，防跨平台身份串联（`docs/eleduck-rules.md` 隐私条目）。
- ✅ 敏感信息纪律：底薪、底线数字、真实在职动态只记本地不入 git（`CLAUDE.md` 约束）。
